# ISR 蛛行六足机器人模拟器设计

日期：2026-11-19  
状态：已确认，待用户复核  
交付形式：离线可运行的单文件 Three.js/WebGL 模拟器

## 1. 目标

在 `E:\root\robot` 中制作一个第三人称六足救援机器人驾驶探索模拟器。视觉质量、镜头反馈和环境氛围接近参考文件 `E:\root\aim\几猫国产3A大作_V1_2.html`，产品结构、运动方式和传感器能力以用户提供的 `ISR-蛛行六足智能搜救机器人-挑战杯（白色高端版）.pptx` 为依据。

核心体验为约 8–12 分钟的夜间城市震后搜救演练。玩家驾驶白色 ISR 机器人穿越灾后城市街区，通过六足步态、传感器扫描、驻停探测和数据上传完成三处生命信号确认。项目不包含射击战斗，不做资源刷取。

## 2. 从需求文档继承的硬性能力

- 机器人为六足仿生结构，每条腿具有髋偏航、髋俯仰、膝俯仰三个关节，共 18 个自由度。
- 腿部使用两连杆逆运动学求解，网页仿真与 PPT 中描述的 STM32 运动内核保持同一套输入输出语义。
- 三角步态分组为 `左前/左后/右中` 与 `左中/右前/右后`，两组相位差半个周期，任意时刻保持三足支撑。
- 支持波动步态，每次仅摆动一条腿，形成五足支撑。
- 原地转向使用两侧足端反向划动形成差动转向。
- 足端压力参与失步反馈，支撑腿压力过低时缩短支撑相、提前摆动并修正落点。
- 提供移动/驻停双模式。移动时优先步态和避障，降低易受振动干扰的毫米波与声音通道权重；驻停后提升热像、人体存在和声音探测精度。
- 展示九类传感器：RGB 摄像头、AMG8833 热像、LD2410B 毫米波、INMP441 麦克风、MQ 气体、VL53L0X 测距、MPU6050 姿态、FSR 足端压力、INA219 电源监测。
- 搜救场景包含障碍、通道、模拟受困人员、热源点和净高约 0.53 米、仅机器人可进入的低矮夹层。
- 输出姿态、传感、任务和扫描结果，为后续接入 WebSocket 实体数据保留清晰的数据边界。

## 3. 玩家体验

### 3.1 场景

地点设定为暴雨后的“临川市 7 号街区救援区”。场景包含：

- 湿沥青街道、倒塌商业楼、倾斜公交与车辆、散落招牌、钢筋、碎石堆、狭窄巷道和积水地铁入口。
- 夜间强雾、动态雨线、破损消防管喷水、闪烁应急灯、琥珀色警示灯和远处断电高楼剪影。
- 可通行坡道、障碍物和边界碰撞体，确保探索路线清晰但不空旷。
- 三处搜索区，分别位于倒塌商铺夹道、半坍塌高架桥下和积水中庭。

### 3.2 任务流程

1. 开局显示 ISR 品牌启动画面和任务简报。
2. 玩家驾驶机器人进入街区，通过方位和信号强度寻找搜索区。
3. 到达区域附近后减速或驻停，使用扫描持续探测。
4. 热源、人体存在能量、声音三项中命中两项后，生成“疑似目标”及置信度。
5. 玩家确认目标并上传数据，进入下一区域。
6. 三处目标确认并上传后显示演练结算，可重新开始自由探索。

## 4. 操作与手感

### 4.1 控制

- `W/S`：前进、后退。
- `A/D`：差动转向。
- `Shift`：加速；加速时镜头后拉并轻微扩大视野。
- `Space`：紧急驻停，速度快速归零并进入稳定姿态。
- 鼠标拖动：环绕第三人称镜头；滚轮调整镜头距离。
- `G`：切换三角步态和波动步态。
- 按住 `R` 或鼠标右键：启动区域扫描。
- `E`：确认目标、操作数据终端、上传数据。
- `H`：显示或隐藏完整控制说明。
- `Esc`：释放鼠标或打开暂停信息。

### 4.2 运动手感

- 机器人具有明显的质量和惯性，起步和停止均使用平滑加速度，不允许贴地滑行。
- 六条腿逐条执行支撑相与摆动相，足端在摆动相抬升、前移、落下，支撑相相对机身后移。
- 三角步态维持交替三足支撑；波动步态一次只抬一条腿。
- 机身随坡度、加减速和转向产生倾斜，镜头只吸收一部分机身运动，形成机械震动但不眩晕。
- 足端落地触发轻微镜头脉冲、液压短促声和对应 FSR 数值变化。
- 扫描时镜头缓慢收紧，机器人姿态稳定，传感器细节展开或亮起。

## 5. 机器人模型

- 机体采用白色陶瓷装甲、深灰金属关节、琥珀警示灯和青蓝传感器光。整机按小型样机比例建模，机身约 0.56 米、腿展约 0.98 米。
- 建模层次为 `robot root -> body -> hip yaw -> hip pitch -> knee pitch -> foot`，每条腿独立，共 18 个可动关节。
- 机体包括主舱、前部传感器云台、顶部天线、侧面模块、散热片、六条三节腿、足端压力垫和状态灯。
- 传感器节点在机体和外设上以不同颜色小型发光点表示，HUD 中选择传感器时同步高亮。
- 六条腿的髋关节与机身同高，足端挂点与脚掌姿态分离校正，足端接触点使用射线检测地面/障碍高度，支撑相和摆动相始终位于地面以上。
- 使用 GTAO、Bloom、运动模糊、SMAA、动态胶片颗粒、电影色调、雨夜天空、湿地反光、涟漪和体积灯光提升画质。
- 建筑包含程序化室内商铺、真实窗格、消防梯、屋顶设备、公交残骸和街面道具；地面包含裂缝、油污、轮胎印和纸屑贴花。
- 模型全部由程序化几何体组成，不依赖外部模型文件或网络资源。

## 6. 步态与物理

- 足端轨迹使用相位驱动的分段曲线：支撑相沿本地地面后移，摆动相沿平滑抬腿曲线前移。
- 三角步态组 A 与组 B 相位相差 0.5；波动步态六腿相位依次错开。
- 根据行进方向和转向速率计算目标足端位置，限制髋关节工作空间。
- 使用两连杆逆运动学把足端位置映射到髋俯仰和膝俯仰角；髋偏航由足端横向偏移计算。
- 支撑相脚掌压力在落地后快速建立，摆动相归零；若支撑足压力低于阈值则触发简短“打滑”反馈和落点微调。
- 使用 Rapier 3D 碰撞层，建筑、车辆、石块、家具和街道道具均有碰撞代理。
- 机体使用 3D 体积检测，髋节、膝节、胫节和脚掌逐段扫掠；不得穿透楼体、车辆、脚手架、围墙、大块混凝土和中型碎块。
- 提供 `P` 键碰撞线框调试视图，用于人工检查代理与视觉网格的一致性。
- 第三人称镜头对楼体、车辆、路灯和大型废墟进行遮挡检测并自动收缩距离。
- 机身姿态由地形高度、速度、加速度、转向和足端支撑状态共同决定，使用阻尼插值避免抖动。

## 7. 传感器与搜救逻辑

### 7.1 移动模式

- 移动时显示测距、IMU、FSR、电源和气体数值。
- 热像、毫米波、声音只提供低权重快速估计，扫描进度增长较慢。
- HUD 提示震动导致高精度通道降权。

### 7.2 驻停模式

- 速度接近零且六足稳定后自动切换为驻停模式。
- 热像、人体存在、声音通道权重提高，扫描进度快速增长。
- 扫描完成后显示证据卡片：方向、置信度、热源强度、人体存在能量、声音事件和 RGB 画面抽象预览。

### 7.3 传感器模拟

- RGB：输出低照度噪声画面代号和视觉状态。
- 热像：每个搜索区具有目标热源强度，接近时数值升高。
- 毫米波：根据距离和遮挡输出人体存在能量。
- 麦克风：输出声音事件等级和方向。
- 气体：随蒸汽区位置变化，显示 CO/VOC 风险提示。
- 测距：输出前进方向障碍距离。
- IMU：输出横滚、俯仰和航向。
- FSR：输出六足压力数组。
- INA219：输出电压、电流和功率。

疑似目标判定采用“三项中至少两项超过阈值”的规则，不做生命体征确认承诺。

## 8. 场景与视觉

- 色调沿用参考页的深灰黑基底、骨白文字、琥珀信号色和冷青传感器色。
- 城市环境以断电线缆、应急车辆灯、破损霓虹、路牌反光和楼体消防灯建立层次，避免把自然场景或普通街道简单替换进来。
- 地面使用湿沥青材质、程序化粗糙度和水洼反射高光，雨滴落在水面的环形扰动以低成本方式模拟。
- 使用方向光、半球光、局部点光、聚光灯和雾共同塑形；关键灯和机器人传感器投射阴影。
- 雨线、雾层、蒸汽、火花和扫描粒子使用 GPU 友好的程序化几何与着色器。
- 机器人白色外壳具有清漆层、金属边缘、污渍和湿度变化，避免塑料感。
- 第一印象由启动画面、机器人近景和灯光切换共同建立；不使用模板化卡片式落地页。

## 9. HUD 与界面

- 启动画面：`ISR` 大标题、`蛛行 / SPIDER-6` 副标题、初始化进度、任务地点和天气信息。
- 顶部左侧：任务目标、搜索区完成数、数据上传状态。
- 顶部中央：罗盘和当前航向。
- 中央：扫描准星、目标方向提示、距离和置信度。
- 左下：步态模式、速度、姿态仪、功率、热负载和六足压力。
- 右下：九类传感器的分组状态与实时模拟数据。
- 底部中央：当前步态、驻停状态和上下文操作提示。
- 界面采用参考页式克制的工业排版、细线框、角标和半透明黑色底板；避免大面积发光和过度动画。
- 桌面键盘为主要输入方式，并提供足够的可视区域适配和清晰的键盘焦点状态。

## 10. 音频

- 使用 Web Audio API 程序化生成，不依赖外部音频文件。
- 包含雨声底噪、伺服电机高频、液压释放、足端落地、警示蜂鸣、扫描脉冲和无线电短音。
- 音频在用户首次交互后初始化，提供静音开关。
- 速度、步态和扫描状态影响音高或节奏，使声音反馈与机械运动同步。

## 11. 技术架构

### 11.1 交付文件

- `E:\root\robot\index.html`：完整离线模拟器，内嵌 CSS、JavaScript 和 Three.js 运行库。
- `E:\root\robot\README.md`：启动方式、操作说明、实现边界和验证记录。

### 11.2 运行方式

- 双击 `index.html` 或通过本地静态服务器打开。
- 不依赖 CDN、外部图片、模型、字体或音频资源。
- 使用 Three.js WebGPURenderer，优先 WebGPU，无法取得适配器时自动降级 WebGL2。
- 后处理使用 TSL：GTAO、Bloom、速度模糊和电影调色；WebGPU 路径额外启用 SSR。

### 11.3 模块边界

- `boot`：加载、初始化、错误提示和首屏。
- `renderer`：场景、相机、灯光、后处理相关渲染状态。
- `robot`：18 自由度模型、关节更新和传感器节点。
- `gait`：步态相位、足端轨迹、逆运动学、地形采样和 FSR 反馈。
- `input`：键盘、鼠标、镜头控制和触控降级。
- `world`：城市街区几何、碰撞体、天气、粒子和搜索区。
- `sensors`：九类传感器状态、移动/驻停权重和目标判定。
- `mission`：目标状态、扫描进度、上传和结算。
- `hud`：DOM HUD、罗盘、数据面板、提示和暂停层。
- `audio`：程序化音效和状态联动。

模块通过一个共享的运行时状态对象通信，避免模块直接读写彼此的 DOM 或内部临时变量。

## 12. 性能与兼容

- 目标为当前开发机 1920×1080 下稳定 45 FPS 以上。
- 限制设备像素比上限，动态雨线、粒子和阴影使用实例化或共享几何体。
- 近景机器人使用完整细节，远处环境降低分段和粒子上限。
- WebGL 不可用时显示明确错误信息和浏览器建议。
- 页面失去焦点时暂停鼠标锁定或降低非必要动画，但保持场景可恢复。

## 13. 验收标准

### 13.1 功能

- 机器人模型和 18 个关节可见、连续运动，不出现关节脱节或腿部翻转。
- 三角步态和波动步态可切换，三角步态在行走时始终保留三足支撑。
- 前进、后退、差动转向、加速和紧急驻停可用。
- 机器人与主要障碍碰撞，不穿透楼体、车辆、脚手架和大型废墟。
- 移动模式与驻停模式自动切换，扫描速度与传感器权重符合设计。
- 九类传感器均有实时模拟数据，FSR 显示六足独立压力。
- 三处搜索区均可完成扫描、疑似目标判定、确认和上传。
- 温度传感器在驻停、距离和视线满足时达到人体温度阈值，并在雷达页显示联系人。
- `F` 自动寻人可规划路径、抵达搜索区、自动扫描，并在证据就绪时等待人工确认。
- `Tab` 雷达页显示机器人朝向、障碍、低矮通道、扫描扇区和已检测人体。
- 任务完成后显示结算，可重新开始。

### 13.2 视觉与手感

- 首屏和进入场景后的画面具有参考页水平的高密度灾后都市质感，不以平面网页布局代替 3D 场景。
- 机器人白色装甲、深色关节、琥珀灯和青蓝传感器清晰可辨。
- 雨、雾、湿地高光、蒸汽和局部灯光共同形成夜景氛围。
- 起步、行走、转向、落地和驻停均有可感知的重量与反馈，不出现明显滑步或镜头抖动过度。
- 1440×900 和 1920×1080 下 HUD 不遮挡核心操作区域。

### 13.3 工程验证

- 浏览器控制台无未处理异常。
- 页面连续运行 60 秒无崩溃、无持续增长的内存或粒子泄漏。
- 启动后机器人可立即操作，首屏加载不依赖网络。
- 通过浏览器自动化验证首帧、键盘移动、步态切换、扫描、目标确认和结算主链路。
- 人工检查画面截图、控制说明、暂停和重新开始流程。

## 14. 非目标

- 不实现实体 STM32/ESP32 通信或 WebSocket 服务端。
- 不训练或运行真实 YOLO 模型；仅模拟视觉识别状态和证据输出。
- 不承诺真实救援性能、越障高度、续航或通信距离。
- 不实现多人模式、射击战斗、开放世界、存档系统或移动端完整操作方案。
- 不使用未经授权的第三方模型、图片、音乐或商用素材。

## 15. 风险与处理

- 单文件体积较大：保留内嵌运行库但压缩应用代码，并设置清晰分区注释。
- 18 自由度实时 IK 可能抖动：限制足端目标和关节角速度，使用阻尼和平滑轨迹。
- 高密度场景可能掉帧：控制阴影灯数量、实例化重复物体、限制粒子预算并提供低画质自动降级。
- 湿地和雨雾可能降低可读性：提高机器人轮廓光和 HUD 对比度，关键路径使用暖色引导灯。
- 参考页代码为压缩合并代码：只复用 Three.js 运行库能力，不复制其游戏逻辑和 HUD 实现。
